# C505 · ข้อมูลสุขภาพของฉัน

ข้อกำหนดผู้ใช้ 2 พ.ย. 2569: เปิดมาอ่านข้อมูลก่อน กดแก้ไขเพื่อเปลี่ยนข้อมูล และใช้ CI เดียวกับแอป

## หลักฐานที่อ่านและการนำมาใช้

- [CDC Plain Language checklist](https://www.cdc.gov/health-literacy/php/develop-materials/plain-language.html): ให้เรียงข้อมูลสำคัญก่อน แบ่งเนื้อหาเป็นช่วงด้วยหัวข้อ และใช้คำคุ้นเคย นำมาใช้กับหัวข้อแต่ละหมวดและลิสต์รายละเอียด แทนการเปิดมาพบฟอร์มยาวทั้งหมด
- [NICE CG183: Documenting and sharing information](https://www.nice.org.uk/guidance/cg183/chapter/recommendations#documenting-and-sharing-information-with-other-healthcare-professionals): แยกสถานะแพ้ยา ไม่มีประวัติที่ทราบ และยังระบุไม่ได้ รวมถึงแยกแพ้ยาออกจากอาการไม่พึงประสงค์ จึงคงข้อมูลแพ้ยาไว้ต้นหน้า และแสดงผลข้างเคียงที่เภสัชกรบันทึกเป็นอีกส่วน ห้ามอนุมานว่าไม่มีจากช่องว่าง

การเปิดแบบอ่านก่อนเป็นการตัดสินใจออกแบบตามโจทย์ผู้ใช้ ไม่ใช่ข้อกำหนดของแหล่งอ้างอิง ไม่ได้ทดสอบกับคนไข้ และไม่ได้อ้างว่าเป็นเวชระเบียนที่ครบตามมาตรฐานทางคลินิก NICE ระบุรายละเอียดปฏิกิริยาและวันที่ซึ่งโมเดลแพ้ยาเดิมยังไม่ได้เก็บเป็น structured fields; หน้านี้ไม่สร้างข้อมูลเหล่านั้นขึ้นเอง

## โครงหน้าและพฤติกรรม

1. เริ่มด้วยการ์ดประวัติแพ้ยา ใต้หัวข้อหน้าข้อมูลสุขภาพของฉัน ไม่มีกล่องชื่อซ้ำ
2. ประวัติแพ้ยา ไม่แสดงข้อความผู้บันทึกใต้รายการตามข้อกำหนดล่าสุด
3. ไม่แสดงการ์ดที่เภสัชกรบันทึกใน C505; ข้อมูลผลข้างเคียงเดิมยังเก็บในโฟลว์รายงานแยกต่างหาก
4. ยาประจำ โรคประจำตัว แพ้อาหาร น้ำหนัก และส่วนสูง ใช้หัวข้อ/ไอคอน ลิสต์อ่านเต็มข้อความ
5. ปุ่มแก้ไขข้อมูลสุขภาพด้านล่าง เข้าร่างแยกจากข้อมูลที่บันทึก

แก้ไขแพ้ยา/ยาประจำ/โรค/อาหารด้วย ยังไม่ทราบ–ไม่มี–ระบุข้อมูล แบบเดียวกับตอนสมัคร เมื่อระบุข้อมูลต้องมีข้อความ น้ำหนักถ้ากรอกต้องมากกว่า 0 ไม่เกิน 500 กก. ทศนิยม 1 ตำแหน่ง ยกเลิกไม่เขียนข้อมูล บันทึกกลับสรุป ไม่ออกจากหน้าไปบัญชี

C505: คนไข้กรอกและแก้ไขประวัติแพ้ยาเองผ่าน textarea พร้อมตัวเลือกยังไม่ทราบ/ไม่มี/ระบุข้อมูล บันทึกตรงได้โดยไม่ขึ้น C513 ไม่ถือเป็นการยืนยันทางคลินิกและไม่เปลี่ยนผลข้างเคียงเป็นแพ้ยา กฎ shared household editor เดิมแยกจาก C505

## เคสและส่งมอบภายหลัง

คง C505.1–.3 เพิ่ม edit, none, invalid, long-text ต่อท้าย คู่มือและลิงก์สร้างจาก registry โดย screens:sync ตรวจ view/edit/cancel/save, unknown/none, validation, data escaping และการแยกผลข้างเคียงด้วย tests/health-record.cjs

Flutter ภายหลังนำโครงข้อมูล/โหมดอ่านแก้ไข/semantic tokens ไปทำ widget ได้ ไม่รวม fixtures/ปุ่ม preview ไม่มีการสร้างโปรเจกต์ Flutter ในงานนี้ การบันทึกยังเป็น state ของต้นแบบ ไม่มี backend ใหม่

ผู้ใช้ปรับดีไซน์ต่อ: การ์ดอ่านข้อมูลทุกหมวดใช้ hdCard เดียวกัน มี header / divider เต็มขอบ / body รวมผลข้างเคียงและน้ำหนัก เอาเส้นสีเน้นด้านซ้ายแพ้ยาออก คงหัวข้อและข้อความแยกความหมายไว้

ส่วนสูงไม่บังคับ ถ้ากรอกต้องเป็นตัวเลขมากกว่า 0 ไม่เกิน 300 ซม. ทศนิยม 1 ตำแหน่ง เก็บที่มาของแพ้ยาเดิมภายในเท่าที่มี แต่ไม่แสดงในหน้าดูข้อมูล

ข้อกำหนดล่าสุด: textarea แต่ละหมวดเป็นข้อความเดียว เก็บและแสดง newline รวมบรรทัดว่าง/บรรทัดซ้ำที่อยู่ภายในข้อความ ไม่มี divider แยกบรรทัด ใช้ divider เฉพาะ header/body ของการ์ด นำทางลัดบันทึกแพ้ยาออกจากหน้าแรกเพื่อลดความสับสนกับข้อมูลสุขภาพ แต่ไม่ลบโฟลว์รายงานอาการหลังใช้ยา

## การแก้ไขรายกล่องล่าสุด
C505 ใช้หัวการ์ด Primary ไอคอนและชื่อสีขาว ไม่มี badge สถานะ ดินสอทุกหมวดเปิด C517 (healthfield) แก้ไขเฉพาะหมวดนั้น แผ่นแก้ไขใช้ segmented unknown/none/set และ textarea หรือช่องตัวเลขตามชนิดข้อมูล บันทึกไม่แตะหมวดอื่น ยกเลิกไม่เขียนข้อมูล เคสเดิมของฟอร์มแก้ไขรวมยังคงรหัสเพื่อไม่ชนลิงก์เดิม แต่หน้าปกติใช้รายกล่อง

## สรุปดีไซน์ล่าสุด: ลดกล่อง (2 พ.ย. 2569)
อ่าน [CDC plain-language checklist](https://www.cdc.gov/health-literacy/php/develop-materials/plain-language.html) ซ้ำ: ข้อมูลสำคัญก่อน แบ่งหมวดด้วยหัวข้อ ตัดข้อความซ้ำที่ไม่ช่วยตัดสินใจ การเลือกใช้รายการพื้นขาวเป็นการตัดสินใจออกแบบตามคำขอ ไม่ใช่ข้อบังคับ CDC และยังไม่ได้ทดสอบกับผู้ป่วย

C505 ใช้พื้นอ่านต่อเนื่อง ไม่มีกรอบการ์ดหรือแถบ Primary ทึบซ้ำทุกหมวด ใช้ไอคอน CI หัวข้อ และเส้นแบ่งบางระหว่างหมวด คงแพ้ยาไว้ต้นหน้า น้ำหนักและส่วนสูงเรียงคู่ท้ายหน้า ดินสอมีพื้นที่แตะอย่างน้อยตาม touch token เปิด C517 เฉพาะหมวดเหมือนเดิม ตัวข้อความแสดงเต็มและคง newline โดยไม่แทรกเส้นแบ่งภายในข้อความ สถานะยังไม่ทราบ/ไม่มีไม่ถูกรวมกัน ไม่เปลี่ยนข้อมูลที่บันทึก
