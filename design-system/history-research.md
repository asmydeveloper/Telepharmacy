# ประวัติการปรึกษาและเจ้าของข้อมูล — 31 ต.ค. 2026

## หลักฐานที่อ่านและนำมาใช้
- [NHS family and carer access](https://www.nhs.uk/nhs-app/help/profile/family-and-carer-access/): เมื่อทำรายการแทนผู้อื่น แสดงบริบทบุคคลและทางกลับโปรไฟล์เดิมชัดเจน จึงคงตัวเลือกเจ้าของประวัติไว้ด้านบน และแสดงชื่อเต็ม/ความสัมพันธ์บนทุกการ์ด
- [MyChart proxy access](https://www.mychart.org/l/en-us/help/proxy/): แยกผู้เป็นเจ้าของข้อมูลกับผู้เข้าถึงผ่าน proxy การกรองรายการในต้นแบบนี้ไม่เปลี่ยนผู้ใช้ที่ล็อกอินหรือผู้รับการปรึกษาใหม่
- [NHS appointments](https://digital.nhs.uk/services/nhs-app/nhs-app-features/hospital-referrals-and-appointments-in-the-nhs-app): เชื่อมการนัด/การปรึกษาที่ผ่านมาเข้ากับเอกสารของครั้งนั้น จึงผูกใบสรุป ใบเสร็จ และติดตามยากับ record เดียวกัน โดยใบเสร็จเปิดจากใบสรุปด้านใน ใช้ระยะเก็บข้อมูลเดิมของต้นแบบ ไม่ยืมระยะเวลาของ NHS
- [GOV.UK summary list/cards](https://design-system.service.gov.uk/components/summary-list/): ใช้หัวข้อที่แยกรายการออกจากกัน และ action ที่ระบุรายการเป้าหมายได้ จึงใช้ร้านยา+วันที่ในส่วนหัว และผู้รับการปรึกษาแยกไว้ท้ายการ์ด และชื่ออาการเป็นหัวเรื่องหลัก ปุ่มอ่านใบสรุปมีชื่อเข้าถึงเฉพาะรายการ
- [NN/g applying filters](https://www.nngroup.com/articles/applying-filters/): หลีกเลี่ยงการรีเฟรชที่ขัดจังหวะการกรอก จึงอัปเดตผลค้นหาเฉพาะลิสต์ ไม่สร้างช่องค้นหาใหม่ทุกตัวอักษร

## ข้อเสนอการออกแบบของโปรเจกต์
โหมดรวมทุกคนเป็นความต้องการผู้ใช้ ไม่ได้อ้างว่าเป็นค่าเริ่มต้นของ NHS ใช้ได้เฉพาะสมาชิกที่ได้รับสิทธิ์ในระบบจริง ไม่มีการเพิ่มสิทธิ์เข้าถึงข้อมูลจากการกรองนี้

เลือกทุกคน/ตัวเอง/สมาชิกด้วยชื่อเต็มและความสัมพันธ์ ใช้ปุ่มรูปโปรไฟล์พร้อมชื่อและความสัมพันธ์ สถานะ aria-pressed รองรับ keyboard และวงสี CI พร้อมเครื่องหมายถูก แยก ongoing จากรายการที่จบแล้ว เรียงล่าสุด แบ่งเดือน ค้นหาอาการ ร้าน เภสัชกร หรือเลขการปรึกษาได้ ล้างคำค้นหาและประเภทโดยคงคนที่กำลังดู ผู้ที่ถูกนำออกจากรายชื่อไม่ถูกแสดงเป็นตัวเอง

C403 เพิ่มกรณีทุกคน รายคน สมาชิกไม่มีประวัติ ค้นหา/ไม่พบ ประเภทการปรึกษา โหลดผิดพลาด และเคสครอบครัวที่ยังดำเนินอยู่ C401 คงรหัสการปรึกษาและระบุเจ้าของใบสรุปชัดเจน

## การตรวจ
Unit tests ตรวจ ownership/filter/sort/record routing และ render ทุกสถานะ โดยไม่ได้เปิด browser ภายนอก Browser ของ Codex ใช้ไม่ได้ (The browser access host is unavailable) จึงยังไม่ได้ตรวจภาพ ภาษาไทยบน viewport จริง หรือ usability กับคนไข้

ปรับตามข้อเสนอผู้ใช้: แถวโปรไฟล์ช่วยจำใบหน้า และคงชื่อเต็มในชื่อเข้าถึงของปุ่มและบนทุกการ์ดตามหลัก identity เดิม มีทุกคนเป็นตัวเลือกลำดับแรก สมาชิกจำนวนมากเลื่อนแนวนอนได้ คงตำแหน่งเลื่อนและ focus หลังเลือก ไม่เปลี่ยนคำค้นหาหรือตัวกรองประเภท

ปรับตามความคิดเห็นล่าสุด: เอาข้อความกำลังดูซ้ำใต้โปรไฟล์ออก คงวง/check/aria-pressed และชื่อในรายการประวัติ ปุ่มประเภทที่เลือกใช้ semantic primary/on-primary ส่วนพื้นรางเป็น neutral-50 เพื่อแยก active ได้ชัด

เคส C403.18–19 ใช้ข้อมูลครอบครัวตัวอย่างเดิมจาก C502 แบบ view-only จำนวนสมาชิก6คน ไม่รวมตัวเอง มีตัวเลือกทั้งหมด8ปุ่ม แถวเลื่อนได้และเปิดให้เห็นคนที่เลือกเมื่อเข้าหน้า โดยไม่เขียน S.family เพิ่มในบัญชี หัวข้อดูประวัติของถูกนำออกตามข้อเสนอผู้ใช้ แต่คงชื่อเข้าถึงของกลุ่มไว้ และย้ายสี/ฟอนต์ของ segmented ไป component กลาง

C403.22 ปรับตามข้อเสนอผู้ใช้: รูปและชื่อร้านยาอยู่ส่วนหัวพร้อมวันเวลา ผู้รับการปรึกษาอยู่ท้ายทุกการ์ดโดยมี label ชัดเจนและชื่อเต็ม/ความสัมพันธ์ แยกจาก action ใบเสร็จและติดตามยา ไม่เปลี่ยน record id หรือเจ้าของประวัติ และเอาชื่อร้านซ้ำในเนื้อการ์ดออก

C403.23 เอาทางลัดใบเสร็จออกจากลิสต์ประวัติตามผู้ใช้ ให้เปิดจาก C401 ใบสรุปของครั้งนั้นต่อไป C402 โดยคง consultation id เดิม ปุ่มติดตามยายังคงอยู่เฉพาะรายการที่มีแผนติดตาม

C403.24 ใช้ reference ของผู้ใช้เป็นรูปแบบ label/value ชิดซ้าย/ขวาในเนื้อการ์ด ไอคอน CI ใช้คู่กับหัวข้อข้อความทุกแถว ไม่เพิ่มผลวินิจฉัยหรือข้อมูลทางคลินิกใหม่ แสดงเรื่องที่ปรึกษาจาก h.topic, เภสัชกรจาก record และสถานะการซื้อเดิม ผู้ใช้ขอเอาหัวข้อประเภทกับข้อความเก็บ1ปีออกจากหน้านี้ จึงคงชื่อเข้าถึงของตัวกรองไว้และไม่ได้เปลี่ยนนโยบายเก็บข้อมูลในระบบ

## ตรวจสถานะจากโค้ดจริง C403.25–30
- การปรึกษา `case.status`: queue, paused, matched, room, closed; ทางออก cancelled, declined, expired, branchclosed อยู่ในคิว/เคส ไม่ใช่สถานะการซื้อยา
- รายการยา `case.order.status`: pending, paid, cancelled, expired
- ประวัติเก่า `S.history` มี bought กับ summary แต่ไม่มี orderStatus จึงแยกได้เพียงซื้อ/ไม่ได้ซื้อ ไม่อนุมานว่า bought=0 คือปรึกษาอย่างเดียว หรือ paid คือรับยาครบแล้ว
- แท็บใช้ทั้งหมด/ซื้อยาแล้ว/ไม่ได้ซื้อยา ส่วนป้ายในการ์ดใช้รอชำระ ยกเลิก หรือหมดอายุเมื่อมีข้อมูล orderStatus หรือคำสั่งซื้อที่ผูกกับ consultation id จริงเท่านั้น
- เพิ่ม orderStatus ลง snapshot เมื่อปิดเคสและ caseItem เพื่อเก็บสถานะใหม่ ไม่เติมสถานะย้อนหลังที่ไม่มีหลักฐาน
- แยก active consultation ไว้ในส่วนยังดำเนินอยู่เดิม ไม่เอาสถานะจัดส่ง/คืนเงินมาปนกับประเภทประวัติที่ยังไม่มีข้อมูลรองรับ
- เอาข้อความลิงก์ดูสรุปออกตามผู้ใช้ คง native button ชื่อเข้าถึงเฉพาะรายการและพื้นที่กดครอบการ์ด ทางลัดติดตามยาแยกการกด ย้ายช่องค้นหาไว้ใต้แท็บ

C403.31 จำนวนในแท็บเป็นจำนวนประวัติที่ตรงกับสมาชิกและคำค้นหา แต่ไม่ใช้ตัวกรองประเภทที่กำลังกดในการคำนวณ เพื่อไม่ให้จำนวนหมวดอื่นกลายเป็นศูนย์โดยผิดความหมาย อัปเดต labels ของปุ่มในที่เดิมขณะพิมพ์เพื่อคง focus

C403.32–34 ปรับตามผู้ใช้เป็น pill แนวนอน ลดรูป32px ชื่อ/ความสัมพันธ์อยู่ขวารูป เพื่อลดพื้นที่แนวตั้ง ยังคงชื่อเข้าถึงเต็ม สถานะ aria-pressed และ check คู่กับสี แถวเต็มขอบและเลื่อนได้ จำนวน/ผลค้นหาคงผูกกับผู้รับเดิม และเคส6คนเป็น view-only ไม่เขียนสมาชิกเข้าบัญชี

C403.35 ตามคำขอล่าสุด เอา check ออกจาก pill ใช้พื้น primary และ on-primary ทั้งชื่อ/ความสัมพันธ์สำหรับคนที่เลือก คง aria-pressed, ชื่อเข้าถึงเต็ม และ keyboard focus พร้อม forced-colors

C403.36 / C502.4 เพิ่มสมาชิกสมมติ3คนใน TP.fresh ตามผู้ใช้: สมศักดิ์ (พ่อ71), วิชัย (คู่สมรส39), ข้าวปุ้น (ลูก3) รวมผู้ใช้เป็น6คน รูปสร้างใหม่ด้วย built-in imagegen และผูก id ร่วมทุกหน้าที่ใช้ profileImage ไม่สร้างประวัติแพ้ยาหรือรายการปรึกษาให้คนใหม่โดยอัตโนมัติ ข้อมูลแพ้ยาระบุ unknown เคสเต็มจำนวนใช้ fullFamilyPreview ที่ตัด id ซ้ำก่อนจำกัดสมาชิก6คน
