# คู่มือเหตุการณ์ทดสอบแอปลูกค้า

เอกสารนี้สร้างจาก registry และเคสที่กดได้ในต้นแบบ ไม่ใช่รายงานว่าทุกเคสผ่าน QA แล้ว และไม่ใช่รายการความเป็นไปได้ทั้งหมดของ production

## วิธีใช้งาน

1. เลือกหน้าจาก “ไปจอ” ในแผงขวา หรือกดเดินโฟลว์ในแอป
2. กดเคสตามรหัสใน “ลองสถานะของจอนี้” เช่น C102.1
3. อ่านคู่มือของเคสในเอกสารนี้ แล้วทดลองแก้ข้อมูลหรือดำเนินการต่อ
4. การเลือกเคสจะเตรียมข้อมูลจำลองแทนแบบร่างเดิม จึงไม่ควรใช้กับข้อมูลจริง
5. สวิตช์จำลองทั้งแอปอยู่ใน “ทั้งแอป” ส่วนเหตุการณ์กลางยังไม่มีปุ่มในแผงขวา

## รหัสและการเพิ่มหน้า

- รหัสหน้า Cxxx และ suffix เดิมยังคงเดิม
- รหัสเหตุการณ์ EV-Cxxx-state ใช้ state key เป็นตัวอ้างอิง ไม่เปลี่ยนตามการเรียงปุ่ม ห้ามเปลี่ยน state key ของเคสเดิม
- เหตุการณ์กลาง EV-GLOBAL-001 เป็นต้นไป ใช้ร่วมทุกหน้า ไม่สร้างสำเนารหัสต่อหน้า
- เพิ่มหน้าหรือ state ใน runtime แล้วรัน `npm run screens:sync` จะสร้างคู่มือและทะเบียนให้ด้วย ตรวจความครบด้วย `npm run screens:check`
- หากเคสมีเงื่อนไขเฉพาะ ให้เพิ่มคำอธิบายชัดเจนใน TP.previewEventPolicy.describe พร้อมทดสอบ prep/action จริง ไม่สร้างปุ่มที่เพียงแสดงชื่อ

## ขอบเขตการจำลอง / Flutter

- แผงขวา ตัวจำลอง และ fixture เป็นเครื่องมือ preview เท่านั้น ไม่ยกเข้า Flutter
- เคสรายหน้าเรียก prep/render/action ที่มีในต้นแบบ ข้อความผลที่ต้องตรวจคือ acceptance checklist ไม่ใช่ผลทดสอบอัตโนมัติ
- เหตุการณ์กลางเป็นการจำลองชั้น UI และระงับคำสั่งจากปุ่ม data-a/submit ไม่ได้ตัดอินเทอร์เน็ตจริง ไม่จำลอง HTTP หรือยกเลิกงานที่เริ่มไปแล้ว
- ปุ่ม navigation ยังใช้ได้ ข้อมูลกรอกไม่ถูกล้าง การกลับปกติไม่ส่งแบบร่างให้อัตโนมัติ
- ระบบจริงต้องต่อ fault injection ที่ service adapter: offline, HTTP 5xx, timeout, latency พร้อมการคืนสถานะและป้องกันคำสั่งซ้ำ
- หลัง payment timeout ต้อง reconcile ด้วย order ID / idempotency key ก่อนส่งใหม่ ไม่ถือว่าล้มเหลวแน่นอน
- การจบแชทไม่เปลี่ยนเส้นตายชำระยา 15 นาทีตั้งแต่ส่งรายการ เวลาในทุกจุดต้องอิง deadline เดียว
- ข้อมูลสุขภาพ การให้ความยินยอม และการชำระจริง ต้องมี validation ฝั่ง server เพิ่มเติม

## หลักฐานออกแบบ

- [W3C: Form notifications](https://www.w3.org/WAI/tutorials/forms/notifications/): แจ้งข้อผิดพลาดใกล้ฟิลด์พร้อมวิธีแก้
- [W3C: Status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html): แจ้งสถานะที่เปลี่ยนโดยไม่ย้ายโฟกัสโดยไม่จำเป็น
- การแยกเคสรายหน้าและเหตุการณ์กลางเป็นการออกแบบเครื่องมือ QA ของโครงการ ยังไม่ได้ทดสอบ usability กับผู้ป่วย
