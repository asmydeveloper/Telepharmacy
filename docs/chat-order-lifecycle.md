# โฟลว์สนทนา → ชำระเงิน → รับยา

ปรับในหน้าที่มีอยู่ C303, C308, C309, C414 และการ์ด C201/C403 ไม่สร้างโฟลว์คู่ขนาน

1. ผู้ปรึกษาเลือกสนทนาและส่งอาการ เภสัชกรซักถามและให้คำแนะนำ
2. เภสัชกรส่งรายการยาในแชท พร้อมราคา จำนวนและวิธีใช้ แล้วถามว่ามีคำถามเพิ่มเติมไหม
3. ระหว่างสนทนายังถามเพิ่มเติมได้ ปุ่มทดสอบส่งยาจะส่งการ์ดก่อนคำถามเสมอ
4. ผู้ปรึกษาตอบไม่มีคำถามเพิ่มเติม → เภสัชกรจำลองยืนยันและปิดเคส (ระบบจริงต้องรอเหตุการณ์ปิดเคสจากเภสัชกร)
5. ผู้ที่อยู่ในห้องถูกพาไป C308 ของรายการเดิม ย่อกลับหน้าแรกได้ แต่เปิดห้องที่ปิดแล้วไม่ได้ ทั้งจากปุ่ม ย้อนกลับ และการเรียกเส้นทางเดิม
6. เริ่มเวลา 15 นาทีเมื่อเปิดหน้าชำระเงินครั้งแรก รายการยาในแชทยังไม่เริ่มเวลา การเปิดซ้ำหรือกลับหน้าแรกไม่ต่ออายุ
7. จ่ายสำเร็จ → รับที่ร้านใช้ C309 เดิม ส่งด่วนใช้ C414 เดิม
8. ส่งด่วน: preparing → calling → delivering → delivered แสดงคำแนะนำเภสัชกรถ้ามี และรายการยาเดิม
9. จัดส่งสำเร็จแสดงการ์ดเสร็จสิ้น แถบย่อจัดส่งหายไป ประวัติยังเปิดดูสถานะได้

## ทดสอบ

- หน้าแรก: case-delivery-preparing / calling / delivering / delivered
- C414: chat-preparing / calling / delivering / delivered
- ปุ่มจำลองฝั่งเภสัชกร: เตรียมยาเสร็จ เรียกไรเดอร์ → รับยาแล้ว → ส่งสำเร็จ
- หมดเวลา: จ่ายรายการเดิมไม่ได้ ต้องให้เภสัชกรทบทวนใหม่ ไม่ต่ออายุเอง
- จ่ายซ้ำ/สถานะส่งยาซ้ำ: ไม่สร้างใบเสร็จหรือถอยสถานะ
- โหมด video คงการทำงานเดิม

## ขอบเขตต้นแบบและ Flutter

ยังเป็นข้อมูลจำลอง ไม่มีการเรียกเก็บเงินจริงหรือเรียกไรเดอร์จริง ระบบจริงต้องใช้เวลาจาก server, payment webhook ที่ตรวจสอบแล้ว, pharmacist close event และ delivery event ของคำสั่งซื้อเดียวกัน UI ต้องรับข้อมูล/ callbacks ผ่าน adapter เมื่อย้าย Flutter ไม่ย้ายแผงทดสอบหรือกรอบ iPhone

## หน้าชำระล่าสุด

C308 แสดงเต็มจอ ไม่มีมือจับหรือการลากปิดแบบแผ่นเลื่อน ปุ่มย้อนกลับคงรายการและ deadline เดิม ที่อยู่รับยาจัดส่งเป็น snapshot จากที่เลือกบนหน้าแรกก่อนเริ่มเคส แสดงอ่านอย่างเดียว ไม่มีเลือก เพิ่ม หรือแก้ไขในหน้าชำระ หากไม่มีที่อยู่เลือกไว้ให้ใช้รับที่ร้าน
